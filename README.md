# swaprise

パネルを入れ替えて揃え、せり上がる盤面で連鎖を狙うアクションパズル。ブラウザで動く。

消去中も手動せり上げは可能。自動せり上がりは消去・停止時間中には進まず、天井接触中・着地の揺れ中・パズル・タイムアタックの時間切れ後は手動でも上げられない。

- ゲームロジックは `src/core/` に閉じ込めた純粋な TypeScript。DOM・Phaser に依存しない
- 描画・入力・音は `src/render/` で Phaser 4 を使う。盤面と効果音はコードで生成し、曲（メニュー・ゲーム中・ピンチ）は音声ファイル（`public/audio/`）を使う。キャラクターやストーリーは持たず、盤面・演出・音だけで成り立つパズルにする
- 見た目は曲の明るさに合わせる。背景は画面ごとの色のある空（`index.html` の `body[data-sky]`。canvas は透明で、`src/render/Background.ts` が切り替え、光の玉を曲の拍に合わせて膨らませる）。タイムアタックの空色は残り時間、CPU戦の空色は自分の積み上がりで変わり、危険は各盤面の外周の赤い光（`src/render/DangerGlow.ts`）で表す。パネルの背後は暗いままに保つ。見出し・ボタンは同梱の丸い書体 Fredoka（`public/fonts/`、OFL）、数字は等幅。揃った瞬間の閃きと破片、連鎖数で大きくなる吹き出し、大きな連鎖の揺れと閃光、勝利と新記録の紙吹雪で手応えを出す
- スマホの高解像度画面でぼやけないよう、canvas は論理サイズ × devicePixelRatio で作り、カメラの zoom で論理座標を保つ（`src/render/hidpi.ts`）
- 60fps の固定 tick で進む決定論的シミュレーション。同じ seed と入力列なら同じ結果になる

## 動かす

```sh
pnpm install
pnpm dev          # http://localhost:5173
pnpm test         # コアのユニットテスト（vitest）
pnpm e2e          # ブラウザでの動作確認（Playwright、headless Chromium）
pnpm build        # dist/ に静的ファイルを出力
```

初回の e2e には `pnpm exec playwright install chromium` が必要。

CI では型チェック・単体テスト、通常 E2E、オンライン E2E を別ジョブで実行する。オンライン E2E は3つの独立したサーバーに分割し、各サーバー内では1件ずつ実行してランダム待機列の混線を防ぐ。`check` はこれらすべての成功を確認する。オンライン E2E の trace は CI の再試行時だけ記録する。手元で記録が必要な場合は `pnpm e2e:online --trace on` を使う。

E2E ジョブは [Playwright 公式 Docker イメージ](https://playwright.dev/docs/docker) 上で実行し、ブラウザとOS依存ライブラリを毎回インストールしない。イメージの取得と pnpm の依存関係復元は必要。`@playwright/test` の更新時は `.github/workflows/ci.yml` の2つのイメージタグもロック済みバージョンに揃える。準備ステップはバージョン一致と Chromium の起動だけを検証し、不一致時にブラウザを再ダウンロードして隠さない。E2E はジョブ全体15分、起動確認2分でタイムアウトする。

## パズルモード

せり上がりのない面を、決められた手数（入れ替えの回数）で全部消す。6 ステージ × 10 面。入れ替えは盤面が静止しているときだけ受け付け、成功した入れ替えを1手と数える（空マスとの入れ替えも1手）。手数を使い切ってパネルが残ると失敗。クリアした面は localStorage に記録し、メニューの面選びに ✓ が付く。

面は `src/core/puzzles.ts` にあり、`pnpm puzzles`（`tools/make-puzzles.ts`）が乱数で作る。静止盤面の幅優先探索（`src/core/puzzle.ts` の `solve`）で「ちょうどその手数で解ける」面だけ残し、解を本物の `Board` で再生して全消しになることを確かめてから書き出す。ソルバーの盤面の進行は Board を粗くしたもの（床に着いたパネルだけが揃い、浮いたパネルは落ちてから揃う）なので、記録した解の再生をテストで毎回確かめている。「1手少なくては解けない」もソルバーの範囲で確かめる。

面の並びは手数・枚数だけでなく「解き方」で散らす。`solutionSignature` が解の各手を技法（H 横・V 縦・F 落として揃える・C 連鎖・D 同時消し・N 消えない準備の手）の並びにし、生成器は面ごとに必要な技法を指定して、同じステージの中で並びが重ならない面を選ぶ。STAGE 1 は1手で技法を1つずつ見せてから2手に進み（横 → 落として横 → 縦＋連鎖 → 連鎖 → 同時消し → …）、STAGE 2 以降は縦・連鎖・同時消し・落下・準備の手を順に回す。手数は STAGE 2 で 2→3、STAGE 4 で 3→4、STAGE 6 で 4→5 と上がり、柄は 3 種から 5 種まで増える。ステージ内で並びが重ならないこともテストで確かめる。

URL パラメータで直接ゲームを始められる。

| パラメータ | 意味 |
|---|---|
| `?mode=endless` / `?mode=timeattack` / `?mode=puzzle` / `?mode=versus` / `?mode=cpu` | メニューを飛ばして開始 |
| `&time=30` | タイムアタックの制限時間（秒）。省略時は120 |
| `&stage=2-3` | パズルの面（`mode=puzzle` のとき）。通し番号（1 始まり）でもよい |
| `&cpu=easy` / `normal` / `hard` | CPU の強さ（`mode=cpu` のとき） |
| `&shock=0` | 対戦でビックリパネルを出さない。数値で1試合の上限枚数を指定 |
| `&seed=123` | 盤面の乱数 seed |
| `&speed=10` | 開始スピードレベル（1〜99） |
| `&bgm=0` | BGM を鳴らさない |
| `&countdown=0` | 開始時の 3・2・1 カウントダウンを飛ばす |
| `&opening=0` | 起動時のオープニングを飛ばしてすぐメニューを出す |

## オープニング

起動するとメニューの前に 4 秒ほどのオープニングが流れる（`src/render/OpeningScene.ts`）。ゲームの仕組みそのものを題字で見せる。

1. パネルを 5×7 のドット文字に並べた "SWAPRISE" が、盤面のように画面の下からせり上がる。次の行と同じく暗いまま
2. 音を鳴らせない環境では、ここで「TAP TO START」（タッチ端末以外は「PRESS ANY KEY」）を出して最初の操作を待つ。音を鳴らせる環境では待たずに続く
3. 止まった列から順に柄が灯る。最初の S は角のパネルがひとつずれていて、カーソルが現れてそれを入れ替えると S が完成する
4. S が揃って消え、W・A・P…と 8 文字が順に連鎖して消える。消えたパネルは破片になって飛ぶ。盤面の吹き出し（枚数・連鎖数）は出さない
5. 閃光のあと文字の題字が中央に現れ、メニューの題字の位置へ上がる。そのままメニューに切り替わり、項目が浮かび上がる

音はブラウザの都合で決まる。AudioContext は最初の操作（タップ・キー）の中でしか動かせず、iOS Safari とホーム画面に追加した iOS の Web アプリ、初めて開くブラウザでは操作まで鳴らせない。Chrome 系はインストール済みの PWA（Android のホーム画面、デスクトップのインストール）と、よく音を鳴らしているサイトでは操作なしで動かせる。オープニングは端末の種類で分岐せず、起動時に AudioContext を作ってその状態で決める（`GameAudio.unlocked`）。動いていればそのまま音付きで続き、止まっていれば「TAP TO START」で待ち、その操作の中で動かして続きから鳴らす。

音の運びは、柄が灯る 0.4 秒のライザー → カーソルの登場と入れ替え → 文字ごとの揃いの音（連鎖数で音程が上がる）と 3 枚に 1 回の pop → 最後の文字が消えたところで連鎖の終わりの音階、まで効果音だけで進み、閃光の瞬間にメニューの曲の 1 拍目と題字の一撃（キック・C のハープの駆け上がり・高い和音）を重ねる。曲は鳴り始めまでの間（0.15 秒）だけ先に始めて拍を合わせ、そのままメニューへ続く（同じ曲なら `BgmPlayer` は鳴らし直さない）。メニュー曲は G major で頭が C の和音なので、一撃のハープと同じ調で重なる。

続きが始まったあとは、キー・タップ・ゲームパッドのどれかで途中でも飛ばせる（待っている間の最初の操作は「始める」で、その次から「飛ばす」）。ゲームからメニューへ戻るときは繰り返さない。`?mode=` の直接開始・招待 URL・`?opening=0` では出さない。縦持ちのスマホでは題字を SWAP / RISE の 2 行にする。ドット文字と並びは `src/render/logo.ts` にあり、`tests/render/logo.test.ts` で確かめている。e2e は `e2e/opening.spec.ts`（鳴らせない環境。AudioContext を作った直後に suspend して再現）と `e2e/opening-autoplay.spec.ts`（鳴らせる環境。Chromium に `--autoplay-policy=no-user-gesture-required` を渡す）。

## メニュー

最上位は 1 PLAYER / VS CPU / 2 PLAYERS の3つ。1 PLAYER を選ぶと ENDLESS / TIME ATTACK / PUZZLE、VS CPU を選ぶと EASY / NORMAL / HARD がその場に出る（Esc か ◂ BACK で戻る）。2 PLAYERS は選択肢が1つなので即開始。各項目の下に中身の説明や記録（ベスト、勝敗、パズルのクリア数）を小さく添える。前回遊んだモードを localStorage に覚え、次に開いたときはそこにカーソルを置く。

下段の RECORDS / SETTINGS / HOW TO PLAY で、記録の一覧、音・振動・全画面の切り替え、操作の説明を開く。キーボードは ↓ で項目の列から下段へ降り、← → で選ぶ。

## 操作

| | 1P | 2P |
|---|---|---|
| カーソル移動 | ←↑↓→ | W A S D |
| 入れ替え | Z / Space / Enter | F / G |
| 手動せり上げ | X / Shift | H / R |

ゲームパッドは1台目が1P、2台目が2P。十字キー・左スティックで移動、A/B で入れ替え、L/R で手動せり上げ。

P で一時停止、R でやり直し、Esc でメニュー、M でミュート（ミュートは localStorage に保存）。

### タッチ・マウス

- スマホは横ドラッグで交換する。触れると選択パネルが表示され、そのまま離すだけでは交換しない。PCでは2枚の境目をクリックしても交換できる
- パネルを横にドラッグしても入れ替わる。指を離さず引き続ければ連続で入れ替わる。入れ替えは1マスずつ順に行い、途中で揃えばその場で消えてドラッグは終わる（揃うパネルを消さずに先へ運ぶことはできない）。入れ替え先の下が空ならパネルはそこで落ち、ドラッグはそこで終わる（谷を越えて運ぶことはできない）
- 盤面を2本の指で押している間は手動せり上げ。盤面の下の「▲ ▲ ▲」が押している間だけ明るくなる
- 縦持ちのスマホでは盤面が画面幅いっぱいになるレイアウトに切り替わる。CPU 対戦は自分の盤面をエンドレスと同じ大きさで描き、CPU の盤面は右に半分の大きさで添える。2P 対戦は同じ大きさの2盤面を並べる
- 盤面の右上の「❚❚」でポーズ。ポーズ画面に RESUME / RESTART / SOUND / VIBRATION / MENU のボタンがある。終了後は盤面に RETRY / MENU が出る
- 端末を回転すると、ゲームを止めずに横向き・縦向きのレイアウトへ置き直す
- 横持ちのスマホでは盤面を画面の高さいっぱいに描き、得点や残り時間は盤面の横に置く。2P 対戦は盤面を左右の端に寄せるので、1台を2人で片方ずつ持って遊べる。ポーズは画面中央下の「❚❚」
- ゲーム中は画面をスリープさせない（Screen Wake Lock API がある端末）
- メニューの SETTINGS にある FULL SCREEN で全画面にする（Android Chrome など Fullscreen API がある端末）。設定は保存され、戻る操作や画面オフで解除されてもゲーム開始・再開のときに取り直す。iPhone の Safari は全画面 API がないので、ホーム画面に追加して開く
- ノッチやホームインジケータの内側（safe area）に収める
- 振動フィードバック（Android など `navigator.vibrate` のある端末）。揃った瞬間・おじゃまの着地・天井接触・終了で震える。自分の盤面だけで、CPU の盤面では震えない。メニューの SETTINGS にある VIBRATION で切り替え、キーボードなら V。iOS Safari は API がないので何も起きない。Android はサイレントモード（マナーモード）だと OS が振動を止めるので、鳴らない場合はまず音量モードを確認する。`/vibrate-test.html` でゲームを介さずに試せる

### モード

- **1P ENDLESS**: スピードレベルは消した枚数（10枚で1）と経過時間（8秒で1）の高い方で上がり、下がらない。時間でも上がるので、遅い人でも1回のプレイは8分ほどで終わる。上手い人は消去で先に上がる。この上がり方はパズル以外の全モードで同じ。上位5件のスコアを localStorage に保存し、メニューの ENDLESS の下にベストを出す。メニューの RECORDS で上位5件の一覧が開く
- **1P TIME ATTACK**: 2分間で何点取れるか。スピードレベルの上がり方はエンドレスと同じ。残り時間は右下に出て、10秒を切ると赤くなる。空色も残り120秒の青紫から、60秒で紫、30秒で桃色、10秒で琥珀色へ滑らかに変わる。最後の10秒は画面下部の光が秒に同期して明滅する。色と明滅はゲームの残り時間に従い、無音でも動き、ポーズ中は止まり、0秒になると明滅を止める。時間内に天井へ届いたらそこで終わり。上位5件をエンドレスとは別に保存する。完走時は「時間切れ」の見出しを出さず、得点と最大連鎖・同時消し・連鎖の記録を大きく表示する。制限時間などを変更したプレイでも同じ大きな戦績画面を使うが、オンライン順位の取得・送信は行わない
- 対戦の結果見出しは日本語設定でも WIN / LOSE / DRAW を使う
- 結果画面の SHARE で得点を共有できる（Web Share API。ない環境ではクリップボードにコピー）
- **VS CPU**: EASY / NORMAL / HARD の CPU と対戦。勝敗数を保存する。スピードレベルはエンドレスと同じ規則で上がり、2つの盤面は高い方に揃える（多く消した側に合わせて両方が速くなる）。自分の盤面に SPEED を出す。CPU は人と同じ制約（カーソルを1マスずつ動かし、カーソル位置でだけ入れ替える）で動く（`src/core/ai.ts`）
  - 手の探し方: 1回の入れ替えで揃う手に加え、横3つ・縦3つを目標にパネルを横へ運ぶ・穴に落とす手順を数手先まで読む。消去中は消えたあとの盤面を目標にして、落ちてくるパネルで揃う手順（アクティブ連鎖）を仕込む。おじゃまに隣接する消しと、消したあとに連鎖する消しを優先し、危険状態では連鎖より高い位置を早く崩す
  - 難易度の差: 読みの深さ（EASY 1手・NORMAL 2手・HARD 4手）、思考の待ち時間（EASY 100F・NORMAL 50F・HARD 20F）、カーソル速度（1マス 16F・10F・6F）、連鎖読みとアクティブ連鎖（HARD のみ）。手が見つからないときはどの難易度でも深く読み直すので、止まったままにはならない
- **2P VERSUS**: 同じキーボードかゲームパッド2台での対戦。スピードレベルは VS CPU と同じ
- **ONLINE**: ログイン不要のオンライン対戦。表示名を入力し、友達へ招待URLを送るか、ランダムに相手を探す。招待では両者の準備完了、ランダムではマッチ成立後の3秒カウントダウンで始まる。両者が希望すれば再戦できる。
  - 招待URLは最後の参加・退出・対戦から24時間有効。LEAVE ROOM は自分の席だけを空けるので、同じURLで入り直せる。両者が退出しても期限内なら再利用できる。期限切れはURLを開いた時点で表示する。
  - 画面を閉じたりタブの復帰情報を失ったりしても、同じブラウザでONLINEを開くと参加中の部屋を確認できる。RESUME HEREでこの画面へ引き継ぐか、LEAVE AND CONTINUEで退出して別の部屋へ進める。別タブのランダム待機も解除できる。
  - 退出は接続中のWebSocketに依存せず、サーバーの受付を確認する。通信に失敗してもRETRY、または次にONLINEを開いたときに再試行する。招待部屋の待機・結果画面で切断した席は60秒で解放し、招待URL自体は24時間維持する。
  - 1試合は最大10分、時間切れは引き分け。設定中も対戦は進む。画面オフや切断では一時停止し、1人につき累計15秒以内なら復帰できる。戻らなければ切断負け、同期ずれやサーバー障害は無効試合。
  - FIND MATCHは接続前にも受付条件を確認する。旧版ならRELOAD、参加中なら復旧操作、日次上限ならリセット時刻を表示する。
  - 無料枠内で運用するため、利用量に応じて受付を停止する。ランダム対戦を先に停止し、招待用の枠を残す。日次枠は日本時間9時に更新される。

スマホで遊ぶときは、同じ Wi-Fi にいる状態で Mac 側を `pnpm dev --host` で起動し、表示される `Network:` の URL をスマホのブラウザで開く。

### PWA

- ビルドすると manifest と Service Worker（vite-plugin-pwa）が付き、Android Chrome は「ホーム画面に追加」でインストールできる。iOS は Safari の共有メニューから「ホーム画面に追加」で全画面になる
- ビルド成果物（本体と曲の mp3、合わせて 8MB 未満）を precache するので、次回からはオフラインでも遊べる。別のプレビューURLとはキャッシュを共有しない
- 新しい版は次に開いたときに、メニューを出す前に「UPDATING…」と表示して切り替える（遊んでいる最中に reload しない）。回線が遅くて確認が終わらないときはそのまま始め、次にメニューへ戻ったときに切り替える
- アイコンは `node tools/make-icons.mjs` がコードから PNG を生成する（`public/icons/`）。画像ファイルを手で描くことはしない
- iOS はサイレントスイッチ（本体横のスイッチ）が ON だと WebAudio の音が全部消える。音が出ないときはまずここを確認する

## 実装している仕様

このジャンルの定番の挙動に合わせている。フレーム数や得点表は公開されている解析値を元にした。

- 6列×12段、下からせり上がる盤面。次にせり上がる行は暗く表示
- 横2マスのカーソルで隣接する2枚（またはパネルと空白）を入れ替える。入れ替えは4フレーム
- 同じ柄が縦横3枚以上で消える。消去中はせり上がりが止まる
- 同時消し（4枚以上）と連鎖。消去で落ちたパネルにだけ連鎖フラグが付く
- アクティブ連鎖。消去中・落下中も入れ替えを受け付ける
- 時間差連鎖。別々に着地した2組が「2, 3」と数えられる
- 得点表は公開されている解析値。3枚消しの13連鎖で累計9,170点、14連鎖以降のボーナスは0、31個消しは0点
- 手動せり上げは1段1点。停止表示中の最初の1段は0点
- 対戦: 同時消し n個 で幅 n-1 の板、n連鎖で幅6・厚さ n-1 の板（上限12段）。8個以上は分離。連鎖の板は1つの連鎖につき1枚で、連鎖が終わってから最終連鎖数で送る（途中の段階では送らない）。同時消しとビックリパネルの板は揃ってから100フレーム待って送り、待っている間に別の同時消しがあれば合流して待ち直す。自分の連鎖中に待ちが明けた板は、連鎖が終わったときに連鎖の板と一緒に送る
- 送った板は52フレーム後に相手の予告に入り、相手の盤面が静止（入れ替え・浮遊・落下・消去・変身のどれもなく、連鎖フラグの付いたパネルもない状態が2フレーム続く）してから降る。消し続けている限り降らないので、連鎖や同時消しを繋いで粘れる。相殺（自分の攻撃で予告の板を打ち消す）は入れていない。粘りは「消し続けて降らせない」で表現する
- おじゃまパネルは隣接するパネルを消すと変身。厚さ1段の板（同時消し・2連鎖）は、いくつ積み重なっていても1度の消去で全部が通常パネルになる。3連鎖以上の厚い板は1度の消去で最下段の1段だけが通常パネルになり、残りはおじゃまのまま隣で消すたびに1段ずつ減る。変身の途中で全段が柄を見せてから上の段がおじゃまに戻る（見た目は「戻ったのに残った」ように見えるが仕様）。同じ種類で触れ合っている板は一緒に変身する
- おじゃまは下に積まれたパネルと一緒に落ちて同じフレームに着地する。落ちたパネルが着地して揃えば、乗っていたおじゃまはその瞬間に隣接しているので変身する。おじゃまの上に乗ったパネルもおじゃまと一緒に落ちる
- 変身で出たパネルには連鎖フラグが付くので、おじゃま返しが成立する
- ビックリパネル（対戦専用の「！」付き灰色パネル）。12枚消すごとにせり上がり行へ1枚混ざり、1試合24枚まで。ビックリパネル同士が3枚以上揃うと「消した枚数−2」枚の灰色の板（幅6・厚さ1段）を送る。灰色のおじゃまと通常のおじゃまは同時に変身しないので、交互に積むとサンドイッチになる
- 天井に触れても消去中・変身中はゲームオーバーにならない。猶予を過ぎるとゲームオーバー
- 高さ 9 以上（12 段のうち上 3 段を残す高さ）に通常パネルまたは着地したおじゃまがあると、BGM がピンチの曲に切り替わる。落下・浮遊中のおじゃまは BGM の判定に含めない。2人で遊ぶ VS 対戦はどちらかが危険なら切り替え、CPU 対戦とオンライン対戦は自分の盤面だけで判定する。各盤面の外周の警告も同じ危険判定を使い、危険な盤面の左右と上端に赤い光を出す。天井接触中は上端を強め、危険を脱すると約1秒で赤みが引く。対戦では相手側の警告はその盤面の外周だけに出す。CPU戦の空色は自分の通常パネルと着地したおじゃまの高さで決まり、6段を超えると紫から赤へ徐々に変わり、12段で最も赤くなる。低くなれば通常色へ戻り、ポーズ中は変化を止める。抜けてから2.5秒経つとゲーム曲を、切り替えた小節の頭から続ける（天井付近では数秒おきに出入りするので、すぐ戻すとピンチの曲の冒頭と同じ小節が交互に何度も鳴る）。曲の切り替えは前の曲の予約済みの音が終わるまで0.15秒出力を絞ってから行う。音声ファイルを読み込めないときの予備の曲は `src/render/bgm.ts` にコードで書いてあり、候補は `tools/bgm-candidates.html` で試聴できる
- メニュー曲は音声ファイル `public/audio/menu.mp3`（Gemini で生成した「The Last Block Standing」。G major、120.5 BPM、32 小節）。頭から鳴らし、9〜30 小節を繰り返す（イントロは 1 回）。区間・継ぎ目の溶かし・閃光に合わせる拍の位置は `bgm.ts` の `MENU_SONG`。ファイルを読み込めないときは合成の予備の曲（C major 132 BPM）を鳴らす
- ゲーム曲は音声ファイル `public/audio/game.mp3`（Gemini で生成した「Triple Tile Cascade」。3 連のノリ、106 BPM、28 小節）。頭から鳴らし、2〜25 小節を繰り返す（`bgm.ts` の `GAME_SONG`）。ピンチの曲から戻るときは、切り替えたときの小節の頭から続ける。読み込めないときは合成の予備の曲（D major 96 BPM）を鳴らす
- ピンチの曲は音声ファイル `public/audio/danger.mp3`（Gemini で生成した「Crisis Mode」。150 BPM、40 小節）。導入の 8 小節は飛ばして 9 小節目のドロップから鳴らし、9〜24 小節を繰り返す（`bgm.ts` の `DANGER_SONG`）。読み込めないときは合成の予備の曲（A minor 150 BPM）を鳴らす
- 画面が隠れたら（画面オフ・別アプリ）曲を止める。ゲーム中はポーズ、メニューでは戻ったときに鳴り直す

## 構成

```
src/core/       ゲームロジック（Board, Game, CPU プレイヤー, 得点表, おじゃま仕様）
src/net/        オンラインの入力同期・接続・状態ハッシュ
worker/         Cloudflare WorkerとDurable Objectsの部屋・待機列
src/render/     Phaser のシーン・描画・入力・音
tests/core/     vitest によるロジックのテスト（ランダム入力の長時間実行も含む）
e2e-online/     実通信での招待・ランダム対戦・再接続のテスト
e2e/            Playwright によるブラウザ動作確認とスクリーンショット
```

## 配信

main への push で GitHub Actions が Cloudflare Workers の `swaprise` にデプロイする（`wrangler.jsonc`）。旧名称の URL（`panepon.*.workers.dev`）には `redirect/` の転送用 Worker を置いていて、新 URL へ 301 で飛ばす。転送用 Worker は自動デプロイの対象外なので、変えたら `pnpm deploy:redirect` で手動で上げる。

オンライン記録は D1 を使う。CI は本番 `swaprise-scores` / PRごと `swaprise-pr-N-scores` を作成・解決して migration を適用する。Cloudflare の既存 API token に **D1 Read/Write** が必要。追跡中の `wrangler.jsonc` の DB ID はローカル用のダミーで、直接本番に deploy せず生成済み設定を使う。開発・手動デプロイ・公開設定の詳細は [オンラインスコア](docs/online-scores.md)。

タイミングは `src/core/constants.ts` の `TIMING` にフレーム数でまとめてあり、手触りの調整はここを変える。消去の点滅・柄を見せる時間・1枚ずつ消える間隔・落下前の猶予は `clearTiming(level)` でスピードレベルに応じて短くなる（レベル1が最長、レベル50以上で最短）。

アクティブ連鎖を仕込みやすいよう、消去後の落下前には18フレーム（0.3秒、レベル50以上は8フレーム）の猶予がある。消去で落ちたパネルは着地後も12フレーム連鎖フラグを保持し、その間に交換を完了して揃えれば連鎖になる。落下先や周囲のパネルを動かして仕込めるが、落下中のパネルそのものは交換できない。

おじゃまの解凍は下から上、各段は右から左に進む。通常パネルになる最下段の色を先に見せ、上段はおじゃまの姿を保つ。全マスのめくり演出後も45フレーム（0.75秒、レベル50以上は24フレーム）待ち、変換完了までは板をその場に留める。この間に周囲を入れ替えて連鎖を仕込める。

オンライン対戦のローカル確認は`pnpm build && pnpm dev:online`でポート8788を開く。`pnpm e2e:online`で複数ブラウザの通信テストを実行する。構成と無料枠の予算は[オンライン対戦の設計](docs/online-multiplayer.md)を参照。
