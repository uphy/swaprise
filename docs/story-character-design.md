# 継ぎ市のストーリーとキャラクターの導入設計

最初にVS CPU・ローカル対戦へキャラ選択を追加し、対戦中と勝敗時のアニメーションの見せ方を決めます。このフェーズを単独で完成・公開できる範囲にします。

将来の構想として、既存の他モードへの人物表示、ニカを主人公にした全9章の本編、住人の依頼と短編を検討します。この文書には将来の仕様案も含みます。着手する範囲と順序は[段階別の実装計画](story-character-implementation-plan.md)を正本にします。VS CPU・ローカル対戦の人物表示（フェーズ1）は実装済みで、本編は未実装です。

| フェーズ | この設計の適用範囲 |
|---|---|
| 1：VSで見せ方を決める | 人物選択、試合中の反応、勝利・敗北・引き分け、配置、再戦 |
| 2：他モードへ広げる | エンドレス・タイムアタック・パズル・オンラインへの追加 |
| 3：第1章を試す | 会話、課題、保存・再開 |
| 4：本編を完成させる | 全9章、地図の変化、難易度、人物の解放 |
| 5：遊びを追加する | 依頼・短編・CPUの個性を必要に応じて選ぶ |

フェーズ1は素材のある人物から直接選べるようにし、物語に連動する解放条件は設けません。全10体の素材や本編の完成を待たずに、実際の対戦で表示を確かめます。

## 1. 設定資料と実装済みの機能を区別する

設計の基準は、2026年9月9日に確認した設定案と、mainの`98cdd49`時点のゲームです。設定資料と生成用スキルを本ブランチへ取り込み、制作素材は`assets/characters/`に保存しました。初回取り込み後の追加生成も同じ配置へ登録します。取り込みの対応先とハッシュは`import-manifest.json`に記録しています。

| 設定資料のパス | この設計で参照する内容 |
|---|---|
| `docs/characters/README.md` | 継ぎ市と通常8人・ボス2人の構成 |
| `docs/characters/world.md` | 昇板、調整盤、街床、競技と負荷試験の関係 |
| `docs/characters/profiles/*.md` | 各人の目的、所作、台詞、成長 |
| `docs/characters/relationships.md` | 二人の関係と秘密を知る範囲 |
| `docs/characters/story-seeds.md` | 固定計画の事件、本編9戦、日常の短編 |
| `docs/characters/art-plan.md` | 立ち絵・アイコンと7種類の動作 |
| `docs/characters/generation-policy.md` | ドット絵の採用版と制作途中の素材の扱い |

現在のゲームには、エンドレス、タイムアタック、全消しパズル、CPU対戦、ローカル対戦、オンライン対戦があります。ストーリーの進行管理、キャラクター選択、キャラクター別AIは新規実装です。

現在の盤面描画と音はコードから生成しています。キャラクター素材の登録・採用版の書き出しと、対戦画面への表示は実装済みです。既存のパネルの柄と色の対応は維持します。

## 2. VSからキャラクターを選べるようにする

通常キャラクターはニカ、ミト、セナ、ロッカ、ユノ、バロ、ピリカ、ヌイの8人です。全体構想では最初から選べます。フェーズ1では素材の揃った人物を対象とし、以下の本編連動の解放条件は後のフェーズで扱います。オルドとイゼルは、本編でそれぞれの章をクリアすると選べるようにします。

対戦だけ遊ぶ人には、CPU対戦でオルド・イゼルを相手に選び、試合を最後まで遊ぶことでも解放します。勝利は条件にしません。この対戦では練習用の会話を使い、本編の秘密は明かしません。人物紹介の追加情報は、解放とは別に本編の進行で管理します。

初期試作では素材が揃った人物だけを表示します。製品版の解放ルールと、制作途中で選べない状態は区別します。

| 場面 | 表示と操作 |
|---|---|
| メニュー | お気に入りの人物を表示し、前回の選択を復元する |
| 1人用の既存モード | 開始前に人物を変更でき、選び直さず再挑戦できる |
| CPU対戦 | 自分・相手の人物と、CPUの強さを別々に選ぶ |
| ローカル対戦 | 1P・2Pが別々に選ぶ。同じ人物も選択できる |
| オンライン対戦 | ロビーで選択し、相手の名前と人物を表示する |
| 結果・記録 | 反応する人物と成績を並べ、記録に選択人物を残す |
| 人物紹介 | 基本紹介、解放済みの追加情報、既読会話を表示する |

既存の記録に人物の情報がない場合は、人物なしで表示します。本編の試験や練習の成績は、既存モードのハイスコアやCPU勝敗に加算しません。

### 2.1 VSの試作で配置と表示寸法を決める

フェーズ1の最初の配置案として、縦持ちではプレイ中の人物を小さなアイコンか上半身表示に抑えます。実際の対戦で見え方を確認して寸法を決めます。大きな立ち絵は開始前と結果に使います。横持ちも盤面と操作部品を先に配置し、余白に人物を収めます。PCは盤面横の余白を使います。

ヌイは布全体、オルドは門の輪郭が分かるアイコンを用意します。小柄な動物の耳や尾も含め、人物ごとに表示範囲と基準点を指定します。相手側（2P・CPU）は左右を反転して自分側と向かい合わせます。道具や衣装の非対称は、実際の対戦で向き合っていない違和感のほうが大きかったため許容します。

### 2.2 動作をゲームの確定した出来事に合わせる

最初に使う素材は、立ち絵、アイコン、待機、ピンチ、成功、おじゃま着地、勝利、敗北、通常終了の9種類です。素材制作の正本は設定側の素材計画に置き、この文書で制作状態を複製しません。

| 状態・出来事 | 反応 |
|---|---|
| 通常時 | 待機を繰り返す |
| 自分の盤面が危険 | ピンチを繰り返す。判定の出発点は`musicDanger.ts` |
| 連鎖・大きな同時消し | 短い成功動作を一度再生する |
| 自分の盤面へのおじゃま着地 | 着地動作を一度再生する |
| 勝利・パズルクリア | 勝利動作の後、最後の姿勢を保つ |
| 敗北・パズル失敗 | 敗北動作の後、最後の姿勢を保つ |
| タイムアタック完走・引き分け | 通常終了動作を使う |

結果は試合中の反応より優先します。短い反応が重なった場合は、着地を成功より優先し、成功の再生中に連鎖が伸びても先頭から再生し直しません。反応後はその時点の危険状態に応じて待機かピンチへ戻します。頻発する場合の再生間隔は実機で調整します。

相手の連鎖発生と、自分へのおじゃま着地は別の出来事です。オンラインでは確定したフレームの出来事に反応し、予測のやり直しや再接続時の再生で同じ反応を繰り返さないようにします。無効試合は勝利・敗北にせず、文字で理由を表示します。

フェーズ2でゲーム中の動作を簡略化する設定を検討し、静止画に切り替えても危険状態と結果を判別できるようにします。

## 3. フェーズ3以降の本編はニカの成長を描く

本編の主人公はニカに固定します。ヌイの修理で依頼者の希望を聞くことや、ミトの旅立ちを受け止めることを、ニカの行動として描くためです。ほかの人物が主人公になる物語は、その人物自身の目的から作る追加の短編にします。

地図には市場、工房、門、中央管理所などの地点を置き、章の順番に選べるようにします。自由移動や経路分岐は本編の初回公開版に含めません。章をクリアすると、橋がつながる、店が開く、地図の記録が増えるといった変化を表示します。

会話画面では立ち絵を大きく表示し、日本語フォントとサイズをスマホで確認します。

1章は「導入会話 → 課題 → 結果 → 終了会話 → 地図更新」の順に進みます。会話中はゲームを進めず、読み返しとスキップを用意します。再挑戦は課題から始められます。

物語の中心は、住人が調査と修理を分担して、安全に動かせる街床と便数を見つけることです。対戦で勝つと相手が考えを変える、という描き方は避けます。オルドの承認とイゼルとの合意には、各章で得た記録と具体的な約束を含めます。

### 3.1 本編9章の課題

設定資料の9戦案を、9章の構成へ広げます。全章を対戦にする方式も可能ですが、住人の仕事を遊びに反映するため、一部をパズルや試運転に置き換えることを推奨します。

| 章・相手 | 必須の課題 | 終了後の変化 |
|---|---|---|
| 1 ミト | 短い操作練習とCPU対戦 | 固定計画を知り、部品探しへ出発する |
| 2 ピリカ | 少ない手数で解く全消しパズル | 小さな住人が使う通路を地図に記す |
| 3 バロ | 古い調整盤でCPU対戦 | 旧市場の道具と入場券を受け取る |
| 4 ヌイ | 荷物の仕分けを表した全消しパズル | 利用者の情報を得て、ヌイの古い縫い目を残して修理する |
| 5 ロッカ | おじゃま処理の練習とCPU対戦 | 点検記録と修理の分担が決まる |
| 6 ユノ | 初期盤面の異なる短い試運転を順に達成 | 通れる道と閉鎖を続ける道が地図に残る |
| 7 セナ | 連鎖を組む機会のあるCPU対戦 | 議事録を共有し、共同案を提出する |
| 8 オルド | 通行承認を得た上でのCPU対戦による試験 | 記録と試験結果を確認し、門が開く |
| 9 イゼル | 新しい時間割への負荷を再現するCPU対戦 | 点検担当と停止条件を決め、縮小した祭りを開く |

章6は、制限時間まで天井に到達せず運転を続ける課題を基本案とします。時間、初期盤面、せり上がり速度は試作で調整します。失敗を物語上の事故にはせず、調整盤でやり直します。

練習は初回に案内し、既に操作を知る人は飛ばせます。パズルは既存の全消し判定を使いますが、物語用の面を別に用意します。既存の60面を本編に必須のものとして流用すると、難易度と章の目的を合わせにくいためです。

### 3.2 難易度と結末

本編の難易度は「やさしい」「ふつう」「むずかしい」から選び、章を始める前と再挑戦時に変更できます。どの難易度でも同じ結末まで見られます。難しい設定のクリアは記録で区別し、物語や通常キャラクターの閲覧条件にはしません。

CPU戦では既存の難易度を出発点にします。パズルは難易度別の盤面・手数、試運転は時間・初期状態で調整します。具体値は未測定であり、この文書では固定しません。

セナの章でも、長い連鎖を勝利条件として強制しません。連鎖の練習と追加目標を用意し、初心者が本編を進める条件はCPU戦の勝利に揃えます。

終幕では全ての道を復旧しません。修理できた場所で祭りを開き、閉鎖が続く区画も地図に残します。追加の依頼や短編では、残った工事と住人の日常を扱えます。

## 4. 個性は所作・会話から始める

初期版にはキャラクターの性能差を入れません。選んだ人物によってパネルの種類、攻撃量、天井の猶予、得点が変わることはありません。

CPUの個性は本編完成後に追加します。ミトは小刻みな消し、セナは連鎖の準備、ロッカは危険な盤面の立て直しを重視する案です。人物の戦い方と難易度を別の設定にし、勝率や試合時間を計測して調整します。

開始時の掛け合いは、関係表にある二人を優先して制作します。専用会話のない組み合わせは共通台詞を使います。ニカとセナの関係や、ヌイとオルドの所作だけでも、プレイの前後で人物の違いを表せます。

時間停止や一列消去などの固有スキルは初期版に含めません。後で試す場合は、物語の個別課題として通常対戦と成績を分けます。

## 5. 本編後は短い依頼と日常を追加する

| 機能 | 推奨する内容 | 着手時期 |
|---|---|---|
| 住人の依頼 | 配達の制限時間付き課題、仕分けパズル、点検の試運転 | 本編完成後の最初の追加 |
| 日常の短編 | セナの人形劇、バロとヌイの店暮らしなどを1課題と会話で描く | 依頼の仕組みと共通化する |
| 思い出の収集 | 入場券、地図、絵葉書を短い説明とともに保存する | 本編の報酬から始める |
| 祭りの連戦 | 好きな人物で連戦し、短い後日談を見る | 本編と依頼の後 |
| 今日の試運転 | 全プレイヤー共通の日替わり盤面で遊ぶ | 日替わり課題を別途設計する |
| 協力プレイ | 別々の盤面で共通の修理課題を達成する | 新しいルールとして別途設計する |
| 工房の模様替え | 依頼で得た小物を飾る | 家具素材と配置画面を別途設計する |

依頼は期限なしで遊べるようにします。日替わり課題を入れても、本編の閲覧や人物の解放をその日の参加に結び付けません。好感度の周回稼ぎや能力の育成も、初期の依頼には追加しません。

## 6. 実装は物語・描画・ゲームルールを分ける

以下の新しいファイル名は配置案です。実装時に責務を保ったまま調整できます。

| 配置案 | 責務 |
|---|---|
| `assets/characters/`と`src/generated/characters.ts` | 制作素材の正本と、採用素材の参照一覧 |
| `src/content/story/` | 章ID、会話ID、登場人物、課題、次の章、地図の変化 |
| `src/story/` | 章の進行、解放条件、保存データの検証。DOMに依存しない |
| `src/render/CharacterView.ts` | 素材の読み込みと、人物の表示・動作 |
| `src/render/StoryScene.ts` | 地図、会話、ゲームへの遷移 |
| `src/core/` | 盤面の初期状態と課題の成否。必要な汎用機能だけ追加 |
| `public/characters/` | ビルド前に生成する採用素材と再生設定。Git管理しない |

既存の`GameScene.ts`を課題の実行に使い、本編から開始した場合は結果を物語へ返します。会話や章の条件を`Board`へ埋め込みません。本編と通常プレイの区別は開始時の情報として渡し、成績の保存先も分けます。

課題はCPU戦、全消しパズル、一定時間の試運転を識別できるデータにします。パズルには専用の面、試運転には初期盤面と制限時間を渡します。最初から汎用のイベントスクリプト言語を作る必要はありません。

### 6.1 保存と再開

新しいlocalStorageキーの案は次のとおりです。

- `swaprise.characters.v1`：前回選んだ人物と、CPU戦による人物の解放。
- `swaprise.story.v1`：内容の版、現在の章と課題、既読会話、クリア済み課題、難易度別の記録。

章番号だけを保存せず、変更しない章IDと課題IDを使います。課題開始前にseed・難易度・内容の版を保存します。プレイ途中で閉じた場合は、その課題の最初から再開します。盤面の途中状態の復元は本編の初回公開版に含めません。

課題成功時は成功状態を保存してから終了会話へ移ります。章の解放と報酬は、その保存済み状態から一度だけ反映します。終了会話を途中で閉じても課題を再実行せず、会話から戻れるようにします。複数課題の章では、完了した課題を繰り返す必要はありません。

保存先が使えない場合はプレイを続けられるようにし、進行を保存できないことを画面で知らせます。壊れた値や未知のIDは検証し、読める既存記録を保ちながら安全な地点へ戻します。内容の更新で古い課題を再現できない場合は、その課題の開始へ戻して変更を案内します。

### 6.2 素材とオンライン

全版の画像・制作履歴は`assets/characters/`でGit管理します。[素材の保存と配信](characters/asset-management.md)に従い、`character.json`と各版の`asset.json`を正本にします。画廊は全登録版を参照します。

画像は採用版だけをゲームに同梱します。制作元、全試作、画廊の比較画像は配信物へ入れません。素材ごとに基準点と実際のコマ座標を持たせ、均等な分割を前提にしません。未採用の動作は、試作中に限り静止画へ戻せるようにします。

PWAでは、初回の正常な取得後にキャラと本編もオフラインで使える構成を目指します。画像追加前後の配信サイズとキャッシュ容量を測り、配信物とキャッシュ対象が一致することを検証します。容量の目標値は3体の試作後に決めます。

オンラインの人物IDは、参加者情報としてサーバーで検証します。毎フレームの入力には追加せず、選択は待機中だけ変更できます。ローカルの解放情報は装飾のための条件であり、競技上の権限には使いません。

人物IDは盤面の状態や同期ハッシュに影響させません。旧クライアントとの接続と、サーバー更新時の扱いはプロトコル変更として検証します。表示側に未知の人物IDが届いた場合は共通アイコンを表示します。

## 7. フェーズ1で決めるものと、その後の構想

フェーズ1の範囲は、VS CPU・ローカル対戦での人物選択、試合中と結果の反応、配置、再戦です。本編9章・地図・会話・物語の保存と再開・初心者向けの練習は後のフェーズで扱います。自由移動、全人物の長編、固有スキル、協力プレイ、工房の配置画面は追加企画にします。

各フェーズの試作では次を決めます。

| 未確定の項目 | 判断に使う確認 |
|---|---|
| スマホの人物表示寸法 | 既存の盤面とタッチ領域を狭めず、3種族を見分けられるか |
| 各章の時間と難易度（フェーズ3以降） | 初心者の試遊とCPUによる試合時間・勝率の計測 |
| 会話量と改ページ（フェーズ3以降） | スマホで読みやすく、再挑戦へすぐ戻れるか |
| 素材のサイズと再生間隔 | 小さな表示での見え方、配信容量、端末上の再生 |

フェーズ1は実際のVS対戦でキャラ選択・反応・結果・再戦を確かめて完了とします。本編を広げる判断は、後のフェーズでミトとの第1章を最後まで遊べる状態にしてから行います。キャラクターの表示だけでなく、会話から対戦へ進み、負けても再挑戦し、再起動後も続きを遊べることを確認します。
