# 見た目と音

描画・入力・音は `src/render/` で Phaser 4 を使う。盤面と効果音はコードで生成し、曲は音声ファイル（`public/audio/`）を区間ループする。色・書体・連鎖の色は `src/render/theme.ts`。

## 見た目

- 見た目は曲の明るさに合わせる。背景は画面ごとの色のある空（`index.html` の `body[data-sky]`。canvas は透明で、`src/render/Background.ts` が切り替え、光の玉を曲の拍に合わせて膨らませる）。全画面の絵を canvas に毎フレーム描くと headless の e2e が遅くなって落ちるので、背景は CSS に任せる
- タイムアタックの空色は残り時間で変わる。残り120秒の青紫から、60秒で紫、30秒で桃色、10秒で琥珀色へ滑らかに変わり、最後の10秒は画面下部の光が秒に同期して明滅する。無音でも動き、ポーズ中は止まり、0秒になると明滅を止める
- CPU 戦の空色は自分の通常パネルと着地したおじゃまの高さで決まり、6段を超えると紫から赤へ徐々に変わり、12段で最も赤くなる。低くなれば通常色へ戻り、ポーズ中は変化を止める
- 危険は各盤面の外周の赤い光（`src/render/DangerGlow.ts`）で表す。危険な盤面の左右と上端に赤い光を出し、天井接触中は上端を強め、危険を脱すると約1秒で赤みが引く。対戦では相手側の警告はその盤面の外周だけに出す
- パネルの背後は暗いままに保つ。見出し・ボタンは同梱の丸い書体 Fredoka（`public/fonts/`、OFL）、数字は等幅
- 揃った瞬間の閃きと破片、連鎖数で大きくなる吹き出し、大きな連鎖の揺れと閃光、勝利と新記録の紙吹雪で手応えを出す。CPU 戦とオンラインでは相手の 4 連鎖以上を自分の盤面に「OPPONENT x4!」と短い音で知らせる
- スマホの高解像度画面でぼやけないよう、canvas は論理サイズ × devicePixelRatio で作り、カメラの zoom で論理座標を保つ（`src/render/hidpi.ts`）
- 縦持ちのスマホでは盤面が画面幅いっぱいになるレイアウトに切り替わる。CPU 対戦とオンラインは自分の盤面をエンドレスと同じ大きさで描き、相手の盤面は右に半分の大きさで添える。2P 対戦は同じ大きさの2盤面を並べる。横持ちでは盤面を画面の高さいっぱいに描き、得点や残り時間は盤面の横に置く。2P 対戦は盤面を左右の端に寄せるので、1台を2人で片方ずつ持って遊べる
- せり上げバーは盤面の直下。せり上げ中は黄色に点灯し、山形が上へ流れる。時間・速度・最大連鎖の行はその下

## 危険判定と曲の切り替え

高さ 9 以上（12 段のうち上 3 段を残す高さ）に通常パネルまたは着地したおじゃまがあると、BGM がピンチの曲に切り替わる。落下・浮遊中のおじゃまは判定に含めない。2人で遊ぶ VS 対戦はどちらかが危険なら切り替え、CPU 対戦とオンライン対戦は自分の盤面だけで判定する。外周の警告も同じ判定を使う。

抜けてから2.5秒経つとゲーム曲を、切り替えた小節の頭から続ける（天井付近では数秒おきに出入りするので、すぐ戻すとピンチの曲の冒頭と同じ小節が交互に何度も鳴る）。曲の切り替えは前の曲の予約済みの音が終わるまで0.15秒出力を絞ってから行う。

## 曲

曲の拍は `audio.beat` で取れる。音声ファイルを読み込めないときの予備の曲は `src/render/bgm.ts` にコードで書いてあり、候補は `tools/bgm-candidates.html` で試聴できる。

- メニュー曲は `public/audio/menu.mp3`（Gemini で生成した「The Last Block Standing」。G major、120.5 BPM、32 小節）。頭から鳴らし、9〜30 小節を繰り返す（イントロは 1 回）。区間・継ぎ目の溶かし・閃光に合わせる拍の位置は `bgm.ts` の `MENU_SONG`。読み込めないときは合成の予備の曲（C major 132 BPM）
- ゲーム曲は `public/audio/game.mp3`（Gemini で生成した「Triple Tile Cascade」。3 連のノリ、106 BPM、28 小節）。頭から鳴らし、2〜25 小節を繰り返す（`GAME_SONG`）。読み込めないときは合成の予備の曲（D major 96 BPM）
- ピンチの曲は `public/audio/danger.mp3`（Gemini で生成した「Crisis Mode」。150 BPM、40 小節）。導入の 8 小節は飛ばして 9 小節目のドロップから鳴らし、9〜24 小節を繰り返す（`DANGER_SONG`）。読み込めないときは合成の予備の曲（A minor 150 BPM）
- 画面が隠れたら（画面オフ・別アプリ）曲を止める。ゲーム中はポーズ、メニューでは戻ったときに鳴り直す
- iOS はサイレントスイッチが ON だと WebAudio の音が全部消える。音が出ないときはまずここを確認する

## 振動

Android など `navigator.vibrate` のある端末で、揃った瞬間・おじゃまの着地・天井接触・終了に震える。自分の盤面だけで、CPU の盤面では震えない。SETTINGS の VIBRATION で切り替え、キーボードなら V。Android はサイレントモードだと OS が振動を止める。`/vibrate-test.html` でゲームを介さずに試せる。

## オープニング

起動するとメニューの前に 4 秒ほどのオープニングが流れる（`src/render/OpeningScene.ts`）。ゲームの仕組みそのものを題字で見せる。

1. パネルを 5×7 のドット文字に並べた "SWAPRISE" が、盤面のように画面の下からせり上がる。次の行と同じく暗いまま
2. 音を鳴らせない環境と、全画面を望んでいてまだ入っていないとき（タッチ端末の既定）は、ここで「TAP TO START」（タッチ端末以外は「PRESS ANY KEY」）を出して最初の操作を待つ。全画面はその操作の中で入り、画面の大きさが変わればオープニングを新しい大きさで出し直す。どちらでもなければ待たずに続く
3. 止まった列から順に柄が灯る。最初の S は角のパネルがひとつずれていて、カーソルが現れてそれを入れ替えると S が完成する
4. S が揃って消え、W・A・P…と 8 文字が順に連鎖して消える。消えたパネルは破片になって飛ぶ。盤面の吹き出し（枚数・連鎖数）は出さない
5. 閃光のあと文字の題字が中央に現れ、メニューの題字の位置へ上がる。そのままメニューに切り替わり、項目が浮かび上がる

音はブラウザの都合で決まる。AudioContext は最初の操作（タップ・キー）の中でしか動かせず、iOS Safari とホーム画面に追加した iOS の Web アプリ、初めて開くブラウザでは操作まで鳴らせない。Chrome 系はインストール済みの PWA と、よく音を鳴らしているサイトでは操作なしで動かせる。オープニングは端末の種類で分岐せず、起動時に AudioContext を作ってその状態で決める（`GameAudio.unlocked`）。動いていればそのまま音付きで続き、止まっていれば「TAP TO START」で待ち、その操作の中で動かして続きから鳴らす。

音の運びは、柄が灯る 0.4 秒のライザー → カーソルの登場と入れ替え → 文字ごとの揃いの音（連鎖数で音程が上がる）と 3 枚に 1 回の pop → 最後の文字が消えたところで連鎖の終わりの音階、まで効果音だけで進み、閃光の瞬間にメニューの曲の 1 拍目と題字の一撃（キック・C のハープの駆け上がり・高い和音）を重ねる。曲は鳴り始めまでの間（0.15 秒）だけ先に始めて拍を合わせ、そのままメニューへ続く（同じ曲なら `BgmPlayer` は鳴らし直さない）。メニュー曲は G major で頭が C の和音なので、一撃のハープと同じ調で重なる。

続きが始まったあとは、キー・タップ・ゲームパッドのどれかで途中でも飛ばせる（待っている間の最初の操作は「始める」で、その次から「飛ばす」）。ゲームからメニューへ戻るときは繰り返さない。`?mode=` の直接開始・招待 URL・`?opening=0` では出さない。縦持ちのスマホでは題字を SWAP / RISE の 2 行にする。ドット文字と並びは `src/render/logo.ts` にあり、`tests/render/logo.test.ts` で確かめている。e2e は `e2e/opening.spec.ts`（鳴らせない環境。AudioContext を作った直後に suspend して再現）と `e2e/opening-autoplay.spec.ts`（鳴らせる環境。Chromium に `--autoplay-policy=no-user-gesture-required` を渡す）。

## 全画面とスリープ

- タッチ端末では全画面を既定で望んでいるものとし、オープニングの TAP TO START で入る（Android Chrome など Fullscreen API がある端末）。指の pointerdown はブラウザの「ユーザー操作」に数えられないので、指は pointerup で要求する。SETTINGS の FULL SCREEN で切り替えられ、設定は保存され、戻る操作や画面オフで解除されてもメニューのタップ・ゲーム開始・再開のときに取り直す。PC は SETTINGS で選ぶまで入らない。iPhone の Safari は全画面 API がないので、ホーム画面に追加して開く
- ゲーム中は画面をスリープさせない（Screen Wake Lock API がある端末）
- ノッチやホームインジケータの内側（safe area）に収める
- 端末を回転すると、ゲームを止めずに横向き・縦向きのレイアウトへ置き直す
