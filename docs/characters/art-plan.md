# キャラクター素材の制作計画

最初は1人につき9種類を揃えます。ニカで見た目と動きを確認してから、ほかの住人へ広げます。ゲームへの組み込みは今後の作業で、ここでは素材の用途と制作順を決めます。

## 最初に揃える9種類

| 区分 | 種類・識別子 | 用途と動き |
|---|---|---|
| 基本画像 | 基準立ち絵 `portrait` | 全身の衣装・小物・左右を固定する参照。人物紹介や選択画面にも使う |
| 基本画像 | 顔アイコン `icon` | 小さな相手表示や参加者表示。基準立ち絵からの切り出しを優先する |
| プレイ中 | 待機 `idle` | 呼吸や瞬きの控えめなループ |
| プレイ中 | ピンチ `danger` | 天井付近の危険が続いている間のループ。焦りや集中を表す |
| プレイ中 | 成功リアクション `success` | 連鎖・大きな同時消しに共通の短い反応 |
| プレイ中 | おじゃま着地 `garbage-land` | 自分の盤面への着地に合わせ、驚く・踏ん張る |
| 結果 | 勝利・クリア `victory` | 対戦勝利とパズルクリアの喜び |
| 結果 | 敗北・失敗 `defeat` | 対戦敗北、天井到達、パズル失敗の悔しさ |
| 結果 | 通常終了 `finish` | タイムアタック完走や引き分けで一息つく |

ピンチの判定は既存の `src/render/musicDanger.ts` を出発点にします。相手の連鎖とおじゃまの着地は別の時点です。攻撃は連鎖終了後に送られ、受け手が消し続けている間は降らないため、着地の反応を相手の連鎖発生に結び付けません。

勝利・敗北を通常終了に流用すると、時間切れや引き分けの意味を取り違えます。切断・再接続・無効試合は共通の文字表示で扱い、専用のキャラ画像は初期制作に含めません。

## ニカの制作順

1. 既存の勝利v4を外見の比較対象にして、基準立ち絵を作ります。人物設定との相違は明示し、服装や左右を確定します。
2. 顔アイコンと待機を用意し、スマホの小さな表示でも特徴が読めるか確認します。
3. ピンチ、成功リアクション、おじゃま着地を揃えます。
4. 既存の勝利v4を基準立ち絵と見比べ、敗北・失敗、通常終了を追加します。
5. 9種類の体格、基準点、色、接続する姿勢を確認します。その後、ピリカとヌイで動物・精霊への適用を確かめ、残りの住人へ広げます。

立ち絵と顔アイコンは静止画です。待機とピンチはループ、短い反応は一度再生して待機かピンチへ戻す想定です。結果は一度再生した後に最後の姿勢を保つか、控えめなループにします。画廊での繰り返し再生は確認用であり、ゲーム内の再生仕様とは区別します。

全身表示と小さな顔表示の両方を確認します。スマホの盤面を狭めない配置は、ゲーム組み込み時に検証します。左右非対称の工具や衣装があるため、相手を向かせるために画像を機械的に左右反転しません。

## 後から増やす素材

追加演出・会話の区分に、登場・準備完了 `intro`、大連鎖 `big-chain`、ピンチ脱出 `relief`、新記録 `record`、会話表情 `dialogue` を置きます。これらは最初の9種類の完成数に含めません。背景とイベントの一枚絵は、物語の場面が決まってから制作します。

## 反応が重なるとき

ゲーム組み込み時は、結果を最優先にし、試合中の反応が結果の絵を上書きしないようにします。短い反応が終わったら、その時点の盤面に合わせて待機かピンチへ戻します。連鎖が伸びるたびに冒頭へ戻すと動作が終わらないため、再生中の成功反応の扱いと再発火の間隔を実機で調整します。

[画廊](gallery/index.html)では、素材の有無と試作・採用などの状態を分けて確認できます。種類の識別子は `assets/characters/actions.json`、素材と採用版は人物ごとの `character.json` と版ごとの `asset.json` に記録します。画廊用データは `pnpm assets` で生成します。
