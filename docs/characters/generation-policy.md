# キャラクター画像の生成方針

## 基本方式

ゲーム用素材はドット絵を基本にする。人物ごとに基準画像を一枚決め、以後の生成ではその画像と短い動作説明を渡す。手描き調の既存素材は比較用に残す。画像生成によるドット絵も、フレーム間の形や色の一致が保証されるわけではない。

背景は均一なマゼンタ `#FF00FF` を指定し、生成後に色を抜いて透過PNGにする。影・グラデーション・市松模様・文字・吹き出しは描かせない。生成時の色は指定値からずれる場合があるため、色抜き後に輪郭の色残りと身体の欠落を確認する。元画像は保存する。

## 動作の頼み方

「落胆している様子」のように、伝えたい感情や動作を短く指示する。手足の動きをコマごとに細かく決めすぎない。固定カメラ、同じ体格・衣装、左上からの読み順を基本条件にする。

コマ数は一律に固定しない。待機など小さな動きは6コマ程度から試せるが、勝利など長い動作には多めのコマが必要になる。まず動作に合う数を生成側に任せ、結果の枚数と動きを確認する。少数コマで生成する実験と、生成後にコマを抜く編集は区別して記録する。

終了後に余計な動きがある場合は、ユーザーが確認した範囲を再生対象にする。元の全コマ版と切り詰めた版は別バージョンとして残す。敗北は落胆した姿勢で終え、立ち直りを自動的に付け足さない。

## 切り出しと再生の確認

- 実際のコマ数と境界を測り、切り出し座標を登録する。等分されているとは限らない。
- 静止した足元などを基準に横位置を揃える。補正あり・なしを比較し、意図した動きまで消さない。腕を含む外接矩形の中央を基準にしない。
- 同じ素材内の表示倍率は原則一定にする。コマごとの自動拡大縮小で体格の違いを隠さない。
- 全コマの再生、冒頭と末尾、明暗の背景、小さな表示で確認する。顔・服のちらつき、横揺れ、瞬き、欠け、意図不明の動きを見る。
- 画廊では選択直後に再生し、末尾の追加待ち時間は0。リピートと速度は素材ごとの `loop` と `fps` に保存する。待機・ピンチは繰り返し、他の動作は一度再生して最終コマで止める。ゲーム内で結果の最後の姿勢を保持する仕様とは区別する。

## 保存と採用

画像・実際のプロンプト・参照画像へのリンク・コマ設定・色抜き条件を残す。既存の画像を上書きしない。モデル名は確認できた情報だけを記録する。

画廊は種類ごとに採用版を優先表示する。採用版がない種類は最新の試作を表示する。新しく生成しただけでは採用版を変更しない。採用の指定は `assets/characters/<人物ID>/character.json` の `adoptedAssets` で管理する。

現時点のニカの採用版：

| 種類 | 版 | 評価 |
|---|---|---|
| 待機 | `nika-idle-pixel-v2` | 単色背景から透過した6コマ版 |
| 勝利 | `nika-victory-pixel-v1` | 18コマ版を暫定採用。物を落とす演出は分かりにくさが残る |
| 敗北 | `nika-defeat-pixel-v4-short` | 落胆した姿勢で終わる9コマ版 |

ニカの立ち絵は `nika-portrait-pixel-v2`、顔アイコンは `nika-icon-pixel-v1` に差し替え済み。ピリカは初回の9種類が採用となり、顔アイコンのみ右下の点を除去したv2を使用する。ヌイは9種類を試作として登録済み。採用版の最新情報は人物の `character.json` の `adoptedAssets` を正本とする。

## ピンチの改善候補

ピンチは状態が続く間に使うため、繰り返し再生とする。現在の既定速度は4fps。現行素材にはループの違和感が残るため、今後は汗が出続ける動きなど、冒頭と末尾が自然につながるアニメーションへの差し替えを検討する。今回は再生成せず、速度と再生設定だけを変更する。

保存先と登録方法は[素材の保存と配信](asset-management.md)を参照する。画廊のデータは正本のJSONから生成する。
