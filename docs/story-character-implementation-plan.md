# 継ぎ市のストーリーとキャラクターの実装計画

人物表示を3体で試し、ミトとの第1章を通して作った後、本編9章へ広げます。通常モードの人物選択とオンライン対応は、本編の進行管理から分けて実装します。

推奨する仕様は[導入設計](story-character-design.md)を正本にします。素材の取り込みと配信用データの生成は完了しました。人物表示と本編の実装は未着手です。工数は、素材の完成状況と第1章の試作結果を見て見積もります。

## 1. 作業の単位と依存関係

| 段階 | 成果物 | 前提 |
|---|---|---|
| P0 | 設定・素材の参照先と、採用素材一覧 | 設定作業との整合確認 |
| P1 | ニカ・ピリカ・ヌイのゲーム内表示 | P0 |
| P2 | 通常モードの人物選択と記録 | P1 |
| P3 | ミトとの第1章、保存・再開 | P1とミトの試作用素材 |
| P4 | オンラインでの人物表示 | P2 |
| P5 | 全9章、10体、練習、地図と人物紹介 | P2・P3 |
| P6 | 本編とキャラ対応を含む公開版の検証 | P4・P5 |
| P7 | 住人の依頼、短編、CPUの個性 | P6 |

P3は10体全員の動作が完成する前に着手できます。会話・保存の動作確認には、採用済みの立ち絵や明示した仮素材を使います。製品版の完成条件と試作の条件は分けます。

各段階は複数のPRに分割できます。通常モードの人物表示を先に公開する場合は、本編への入口を完成前に出しません。部分公開する人物は、素材不足と物語上の未解放を同じ表示にしないようにします。

## 2. P0：設定と採用素材を参照できるようにする

- [x] 設定資料の採用版を確認し、`docs/characters/`を実装ブランチから参照できる状態にする。
- [x] 設定資料の変更が続いている場合は、実装が参照する版を記録する。
- [x] ニカ・ピリカ・ヌイの各素材について、採用・試作・未作成を区別する。
- [ ] 第1章に必要なミトの素材と、地図・会話背景の最小構成を決める。
- [x] ゲームに同梱する素材だけを列挙し、画廊全体のコピーを避ける。
- [x] 画像を使う方針をREADMEと開発規約へ反映する作業を用意する。

完了条件は、設定・素材の参照先と不足が一覧で分かり、実装側で勝手に採用版を変更しなくて済むことです。初回は設定用worktreeの資料・スキルと全生成ファイルを取り込みました。採用指定を変更せず、元worktreeも残しています。以後は[素材管理](characters/asset-management.md)の手順で登録します。

登録・書き出しには`tools/character-assets.mjs`を使い、`pnpm assets:check`と`pnpm test:assets`で検証します。第1章用のミト・地図・背景の素材選定は残っています。

## 3. P1：3種族の表示と反応をゲームで試す

主な対象は`CharacterView`、人物と素材の定義、`GameScene.ts`、`theme.ts`です。実装前に既存の画面寸法と操作領域を記録します。

- [ ] 人物IDから立ち絵・アイコン・各動作を引けるようにする。
- [ ] 素材ごとのコマ座標、基準点、再生速度、繰り返しを扱う。
- [ ] 通常・ピンチ・短い反応・結果の優先順位を実装する。
- [ ] 成功と着地を別の出来事として扱い、同じ反応の連続再生を抑える。
- [ ] 縦持ち、横持ち、PCに人物を配置し、結果画面では大きく見せる。
- [ ] 動作を簡略化する設定と、素材が不足する試作時の静止画表示を用意する。
- [x] 採用素材をPWAの配信とキャッシュ対象に含める。

完了条件は、3体とも小さな表示で判別でき、盤面・せり上げ・ポーズのタッチ領域を妨げないことです。勝利の後に着地反応が割り込まず、引き分けと完走には通常終了を使います。

検証では反応の優先順位を単体テストにし、ブラウザではピンチへの出入り、着地、結果、回転を確認します。ドット絵の輪郭、ヌイの全体、ピリカの尾は実機で目視します。

## 4. P2：通常モードに人物選択を追加する

主な対象は`MenuScene.ts`、`GameScene.ts`、`highscore.ts`、`share.ts`、保存処理です。

- [ ] 1人用で前回の人物を復元し、そのまま開始・再挑戦できるようにする。
- [ ] CPU対戦で自分・相手・難易度を独立して選べるようにする。
- [ ] ローカル対戦で別々の人物を選べるようにし、同キャラ対戦にも対応する。
- [ ] 記録に選択した人物IDを保存し、人物IDのない旧記録も読み込めるようにする。
- [ ] 共有文に人物名を追加する。画像付き共有は追加機能として分ける。
- [ ] CPU戦によるボス解放を保存する。
- [ ] 通常モードと、本編・練習の成績保存を分離する。

完了条件は、人物を替えても盤面のルールと成績の算出が変わらず、旧記録が失われないことです。素材未完成の人物を製品版の解放済み選択肢として出す作業は、素材の完成後に行います。

検証では同じseedと入力列で人物だけを変え、盤面・得点・勝敗が一致することを確認します。選択の復元、CPU難易度との独立、同キャラ対戦、未知の人物IDの扱いを確認します。

## 5. P3：ミトとの第1章を通して作る

主な対象は`src/content/story/`、`src/story/`、`StoryScene`、既存ゲームへの開始・結果の受け渡しです。

- [ ] 固定計画を知り、部品探しへ出発する第1章の脚本を確定する。
- [ ] 地図から開始し、導入会話、任意の操作練習、CPU戦、終了会話へ進める。
- [ ] 勝利・敗北・引き分けに対応し、敗北と引き分けから再挑戦できるようにする。
- [ ] 会話スキップ、読み返し、メニューへの帰還を実装する。
- [ ] 章と課題のID、内容の版、難易度、seedを保存する。
- [ ] ゲーム途中は課題の最初から、成功後は終了会話から再開する。
- [ ] 保存先が使えない場合も遊べるようにし、保存できない旨を表示する。
- [ ] 再読込や再通知で、章の解放・報酬・成績が重複しないようにする。

完了条件は、初回プレイと再開の両方で第1章が完結することです。終了会話を閉じても試合をやり直さずに続けられ、本編の勝敗が通常のCPU戦の記録へ混ざらないことを確認します。

試遊では、会話からゲームへ進むまでの待ち、再挑戦のしやすさ、読みやすさを確認します。ここで決めた会話量・画面寸法・保存方法を、残りの章へ展開します。

## 6. P4：オンラインの参加者情報に人物を追加する

主な対象は`src/net/protocol.ts`、`session.ts`、`OnlineScene.ts`、参加者情報を扱うWorkerと部屋の状態です。

- [ ] 人物IDを参加者情報へ追加し、サーバーで値を検証する。
- [ ] 人物の変更を待機中だけ受け付け、準備完了後の扱いを両者で揃える。
- [ ] 再入室・再接続後も人物を復元する。
- [ ] 未知の人物は共通アイコンへ戻す。
- [ ] 確定済みフレームから反応を発火し、同じ試合・フレーム・出来事を二重に再生しない。
- [ ] 切断復帰の追いつき処理で、過去の反応をまとめて再生しない。
- [ ] 無効試合、引き分け、切断負けの表示を確認する。
- [ ] プロトコルの版と旧クライアントの扱いを決め、更新時の接続を検証する。

完了条件は、各参加者が選んだ人物が両方の端末で同じように表示され、人物を替えても入力同期と盤面のハッシュが変わらないことです。人物選択のために毎フレームの通信量を増やしません。

既存のオンラインテストに、同キャラ、再接続、未知の人物ID、準備完了後の変更要求、反応の重複防止を追加します。

## 7. P5：本編9章と10体へ広げる

全員の素材完成と、課題・脚本の制作を分けて進めます。各章の人物の事情を変える場合は、設定資料の正本も揃えます。

- [ ] 本編用の全消しパズルを作り、規定手数の解を実際のBoardで再生する。
- [ ] 章6の試運転に必要な初期盤面・時間・成否の判定を追加する。
- [ ] 消去途中も操作できる連鎖練習と、おじゃま処理の練習を作る。
- [ ] 第2章から第9章までの会話・課題・地図更新を作る。
- [ ] 全10体の採用素材を組み込み、通常8体とボス2体の解放条件を適用する。
- [ ] 基本紹介、進行後の追加紹介、既読会話を分けて表示する。
- [ ] 難易度変更と難易度別記録を、CPU戦・パズル・試運転で揃える。
- [ ] オルドの承認、イゼルとの合意、祭りの終幕を脚本と画面の両方で確認する。

完了条件は、全難易度で同じ結末に到達でき、途中のどの課題からでも再開できることです。章6の途中まで進めた状態、ボス解放の前後、全章クリア後からの再挑戦も確認します。

CPU戦の調整ではCASUALを使い、各章・各難易度について試合時間と勝率を記録します。変更前後で同じseed集合を使い、標本数と条件を残します。平均だけでなく、最短・中央値・長い試合も比較します。人の初心者による確認も行い、CPUの数値だけで読みやすさや遊びやすさを判断しません。

## 8. P6：公開前に保存・表示・配信を確認する

| 観点 | 必須の確認 |
|---|---|
| ゲーム | 既存モードのルールと成績が変わらない |
| 進行 | 課題開始前・途中・成功直後・会話途中の再読込で戻れる |
| 保存 | 旧データ、壊れた値、保存不可、内容の版の違いを処理できる |
| 物語 | 人物がまだ知らない秘密を話さず、勝敗だけで人格が変わらない |
| スマホ | 縦横の回転、タッチ領域、会話、ボタン、3種族の表示を確認する |
| オンライン | 再戦・再入室・切断復帰・無効試合で人物と結果が正しい |
| PWA | 初回取得後に、本編と人物がオフラインで表示される |
| 素材 | 配信サイズとキャッシュ容量を記録し、試作画像が混入していない |

変更に応じて`pnpm typecheck`、`pnpm test`、`PREVIEW_PORT=4175 pnpm e2e`を実行します。4175は候補で、使用中なら空いているポートへ変更します。オンラインに触れたPRでは`pnpm e2e:online`も実行します。AIや速度・難易度を変えた場合は、`pnpm sim`と必要なバランステストを追加します。

既存の不具合を直すときは、修正前に新しいテストが落ちることを確認します。e2eの表示待ちは状態を条件にし、固定時間の待ちに頼りません。

レイアウトやタッチ操作を変えたPRは、CIのプレビューURLをスマホで開き、ビルド識別子を照合してからmergeします。mainへのmergeで配信されるため、未完成の本編への入口や仮素材が公開されないことも確認します。

## 9. P7：短い依頼とキャラの戦い方を追加する

- [ ] 本編と共通の課題・会話の仕組みで、住人の依頼を少数作る。
- [ ] 日常の短編を、関係表の組み合わせから制作する。
- [ ] 本編や依頼で得た地図・入場券・絵葉書を読み返せるようにする。
- [ ] ミト・セナ・ロッカのCPUの戦い方を試し、難易度と分離する。
- [ ] CPUの変更前後で勝率・試合時間・連鎖や同時消しの傾向を計測する。

完了条件は、短く遊べる依頼が増え、人物の違いが会話とプレイの両方から分かることです。日替わり課題、協力プレイ、工房の模様替えは、この段階の必須条件には含めません。

## 10. 各作業の引き継ぎに残すもの

各PRには、変えた動作と理由、確認した条件、残っている制約を記載します。バランスを変えた場合は計測条件と前後の数値を残します。

素材の追加では採用元とゲームに同梱する版を記録します。物語の変更では影響する人物設定・会話・解放条件を揃えます。作業は専用worktreeで行い、コミットには自分が変更したファイルだけを含めます。
