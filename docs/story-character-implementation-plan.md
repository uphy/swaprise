# キャラクター表示から始める段階別の実装計画

最初のフェーズは、VS CPUとローカル対戦でキャラを選び、対戦中・勝利・敗北の見せ方を決めることに絞ります。このフェーズだけで公開できる範囲にし、ストーリーやオンライン同期の実装を完了条件に含めません。

[導入設計](story-character-design.md)は将来の本編まで含む構想です。この実装計画で、今回作る範囲と後から判断する範囲を分けます。素材の取り込み・採用管理・配信用データの生成は完了し、フェーズ1のVS CPU・ローカル対戦への人物表示を実装しました。

## 1. 各フェーズで遊べるものを増やす

| フェーズ | 遊べるもの・決めること | 着手の前提 |
|---|---|---|
| 1 | VS CPU・ローカル対戦で人物を選び、試合中と結果の演出を確かめる | 取り込み済みの素材を使う |
| 2 | エンドレス・タイムアタック・パズル・オンラインにも人物を表示し、対応キャラを増やす | フェーズ1で表示と反応を決める |
| 3 | ミトとの第1章を、会話から保存・再開まで通して遊ぶ | 対戦画面を再利用できる状態にする |
| 4 | 地図と課題を追加し、本編9章を完成させる | 第1章の試遊で物語を広げる判断をする |
| 5 | 住人の依頼・短編・CPUの戦い方を追加する | 本編完成後に優先順位を決める |

フェーズ2では、エンドレス・タイムアタック・パズルへの対応と、オンラインへの対応を別々に公開できます。以降の全フェーズを一度に実装する計画にはせず、各段階を遊んでから次の範囲を決めます。

## 2. フェーズ1：VSのキャラ選択と演出を作る

### 対象モードと人物

VS CPUと、同じ端末で遊ぶ2 PLAYERSを対象にします。自分と相手の両方を表示でき、勝敗やおじゃまの反応を確認できるためです。CPUの難易度は人物と別に選び、人物による性能差は付けません。

素材はニカ・ピリカを出発点にします。取り込み時点ではピリカに9種類、ニカに5種類の採用素材があります。最新の採用状況は`character.json`で確認します。全10体や3種族の素材完成を、着手の条件にしません。

不足する動作は通常の静止画で代替し、試作用の表示であることが分かるようにします。試作素材を使って比較する場合は開発用の選択に限定し、`adoptedAssets`を勝手に更新しません。ヌイ・オルドのような輪郭の違う人物は、後の表示確認にも使います。

### 作るもの

- [x] VS CPUで自分と相手の人物を選べるようにする。
- [x] ローカル対戦で1P・2Pが人物を選び、同キャラ対戦もできるようにする。
- [x] 選択後に対戦へ進み、再戦では同じ組み合わせを引き継ぐ。
- [x] メニューへ戻って人物を変更でき、前回の選択を保存できるようにする。
- [x] 対戦中に両者の人物を表示し、盤面ごとに反応させる。
- [x] 勝利・敗北・引き分けで、結果に合う動作を再生する。
- [ ] スマホの縦持ち・横持ちとPCで、表示位置と大きさを比較する（最初の配置は入れた。実機での調整は 1-D）。

実装先は`src/characters/`（人物の一覧・選択の保存・反応の優先順位。DOMに依存しない）、`src/render/CharacterView.ts`（素材の読み込みと表示）、`MenuScene.ts`の人物選び、`GameScene.ts`の配置と出来事の受け渡し。素材のない動作は待機で代替し、待機もない人物は色の札に名前を出す。代替中は足元に動作名を出す。選択は`swaprise.characters.v1`に保存する。

対戦前の長い掛け合い、キャラ解放、人物紹介、人物別の成績や画像共有はフェーズ1に含めません。人物は素材の揃った範囲から直接選べるようにします。エンドレス・タイムアタック・パズル・オンラインへの導入も後のフェーズです。

### プレイ中と結果の見せ方を決める

| 状態・出来事 | 試す動作 | 確認すること |
|---|---|---|
| 通常 | 待機 | 繰り返しても盤面に集中できるか |
| 自分の盤面が危険 | ピンチ | 両者それぞれの状態が伝わるか |
| 連鎖・大きな同時消し | 成功 | 発生頻度と長さが適切か |
| 自分へのおじゃま着地 | 着地反応 | 相手の連鎖時点と混同していないか |
| 勝利 | 勝利動作 | 最後の姿勢と結果表示が合っているか |
| 敗北 | 敗北動作 | 悔しさが伝わり、再戦操作を妨げないか |
| 引き分け | 通常終了 | 勝利・敗北と見分けられるか |

結果を最優先にし、終了後に成功や着地の反応を割り込ませません。短い反応の後は、その時点の状態に合わせて待機かピンチへ戻します。連鎖が伸びるたびにアニメーションの先頭へ戻さず、頻繁な反応の扱いを試遊で決めます。

「対戦中は小さく、開始前・結果では大きく表示する」を最初の配置案とします。盤面とタッチ領域を先に確保し、人物が読める表示寸法を探します。結果画面では人物の動作を再生しながら、待たずに再戦・メニューを選べるようにします。

画像の倍率と基準点は人物ごとに扱います。相手側（2P・CPU）は左右を反転して向かい合わせます。反転しないと対戦相手と向き合っていない印象が強かったため、道具や衣装の非対称は許容します。ドット絵の拡大方法もこのフェーズで確認します。

### 作業の順番

| 作業 | 確認できる状態 |
|---|---|
| 1-A 表示と選択 | 人物を選んで対戦でき、待機する両者を見られる |
| 1-B 試合中の反応 | ピンチ・成功・着地を、実際の盤面の動きで確認できる |
| 1-C 結果と再戦 | 勝利・敗北・引き分けから再戦と人物変更へ進める |
| 1-D 実機で調整 | 配置、倍率、反応頻度、結果の見せ方を決める |

主な実装先は`CharacterView`、`MenuScene.ts`、`GameScene.ts`、`theme.ts`、選択の保存処理です。表示の都合で盤面のルールを変えず、ゲームの出来事から反応を選びます。

### 完了条件

フェーズ1の完了は、以下を満たし、プレビュー版をスマホで確認できた時点とします。

- キャラ選択から対戦、結果、再戦、人物変更まで一通り遊べる。
- 人物が盤面や操作部品を隠さず、縦横の回転後も表示が崩れない。
- 自分と相手の反応が正しく、結果の動作が途中の反応に上書きされない。
- 再戦操作がアニメーションの終了待ちにならない。
- 使用する素材と不足時の代替表示が決まり、採用未定の版を製品用データへ混ぜない。

本編の脚本や全10体のアニメーション完成は、この完了条件に含めません。

### 検証

反応の優先順位と前回選択の復元を単体テストで確認します。同じseedと入力列で人物だけを替え、得点・勝敗・盤面が一致することも確かめます。

ブラウザでは選択、同キャラ対戦、成功・着地・ピンチ、勝利・敗北・引き分け、再戦、回転を確認します。既存の`window.__swaprise`で盤面を組み、偶然の勝敗を待たずに各結果を再現します。表示待ちは状態を条件にします。

`pnpm typecheck`、`pnpm test`、対象のe2eを実行します。レイアウトを変えたPRはCIのプレビューURLをスマホで開き、ビルド識別子を照合してからmergeします。

## 3. フェーズ2：確定した表示を他のモードへ広げる

エンドレス・タイムアタック・パズルでは好きな人物を選び、パズルのクリア、タイムアタック完走、天井到達などに反応させます。対応人物を増やす際に、動物・精霊の表示寸法と基準点を確認します。

オンラインは別の作業として扱います。人物IDを参加者情報に加え、待機中の変更・再接続・再戦へ対応します。人物IDを入力や同期ハッシュに含めず、確定済みの出来事から反応を再生します。復帰時の過去の反応の連続再生や、予測のやり直しによる二重再生を防ぎます。

人物紹介、人物別の記録、共有文への人物名の追加、動作を簡略化する設定は、このフェーズで必要性を判断します。オンラインの変更には既存の接続・復旧テストと`pnpm e2e:online`を追加します。

## 4. フェーズ3：第1章で物語の遊び心地を確かめる

ニカとミトの会話、任意の操作練習、CPU戦、終了会話をつなぎます。第1章用の素材、最小限の背景と地図を用意し、会話スキップ・読み返し・保存・再開を実装します。

課題の途中で閉じた場合は、その課題の最初から再開します。成功後は終了会話から戻れ、本編の成績は通常モードへ加算しません。保存不能・古い内容の版・報酬の重複も扱います。

完了条件は、第1章を初回と再開の両方で最後まで遊べることです。会話の長さ、ゲームへ進むまでの待ち、負けた後に再挑戦したくなるかを確認し、本編を広げる判断をします。

## 5. フェーズ4：本編を9章へ広げる

導入設計の9章を基に、専用パズル、試運転、連鎖とおじゃま処理の練習を追加します。地図の変化、難易度選択、人物の解放、進行に応じた紹介を作ります。

どの難易度でも同じ結末まで到達できるようにします。CPU戦のバランス変更は同じseed集合とCASUALで前後を比較し、標本数・勝率・試合時間を残します。初心者の試遊も行います。

完了条件は、全9章を遊べて、各課題から再開できることです。オルドの承認、イゼルとの合意、規模を縮めた祭りの結末を、脚本と画面の両方で確認します。

## 6. フェーズ5：短い依頼と人物の個性を追加する

本編の課題と会話を再利用して、住人の依頼や日常の短編を作ります。思い出の収集、祭りの連戦、CPUの戦い方の違いは、本編完成後の優先順位で選びます。

協力プレイ、日替わり課題、工房の模様替え、固有スキルは追加企画です。この計画では実装を約束せず、それぞれのルールと制作量を検討してから着手します。

## 7. 取り込み済みの素材基盤を使う

設定資料、生成スキル、232ファイルの制作素材、画廊を取り込み済みです。全版は`assets/characters/`で管理し、採用版だけを配信用に生成します。登録方法は[素材管理](characters/asset-management.md)を参照してください。

`pnpm assets:check`と`pnpm test:assets`で素材定義と出力を確認します。`pnpm dev`と`pnpm build`は採用素材を自動生成します。素材を追加した際はPWAの容量とオフライン表示も確認します。

各フェーズの作業は専用worktreeで行い、PRには変更理由と検証結果を残します。現在の取り込み済みブランチを引き継ぐ場合は、素材基盤を作り直す必要はありません。
